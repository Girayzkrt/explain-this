# Security policy

## Reporting a vulnerability

Please report security issues **privately**, not in a public issue.

Use GitHub's [private vulnerability reporting](https://docs.github.com/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)
on this repository. If that is not enabled, use the private maintainer contact published
in the repository's About section or profile.

When reporting, please include the extension version, your Chrome version, your operating
system, and the steps to reproduce. **Do not include page text you were reading**, model
output, or anything else private — a description of the mechanism is enough.

## Scope

This extension's own code runs entirely on your machine and talks only to a local Ollama
server on loopback; it never opens a connection anywhere else. In **Ollama Cloud** mode,
that local Ollama server forwards your selection on to Ollama's servers — see the mode
table in [`docs/privacy.md`](docs/privacy.md) for exactly what goes where. Reports are
most useful when they concern:

- reading page content the user did not select, or sending it anywhere;
- escaping the reader's Shadow DOM sandbox, or executing model output as code;
- obtaining host permissions beyond the approved loopback origins without user consent;
- writing page text or model output to persistent storage;
- reaching a non-loopback endpoint.

## Known and accepted limitations

These are documented rather than treated as vulnerabilities, because they are properties
of the models this extension can run — local or cloud — rather than defects in the
extension:

- **Prompt injection is not prevented.** A hostile page can contain text that steers the
  model, and every small local model evaluated complied readily. Evaluation across four
  models found no model that resisted every case, and adding a trust-boundary reminder
  after the untrusted text did not help. What _is_ enforced: model output is rendered as
  sanitised Markdown and cannot execute, create links, or inject DOM; the extension has
  no network egress beyond loopback; and, in the default **On this computer** mode, page
  text never leaves your device. In **Ollama Cloud** mode it goes to Ollama's servers as
  normal for that mode — an injection cannot route it anywhere beyond that. A successful
  injection changes the wording shown in the reader card and nothing else.
- **Model output can be wrong.** Explanations are generated by the model you chose —
  local or cloud — and are not verified.

See [`docs/privacy.md`](docs/privacy.md) for the full data inventory.
